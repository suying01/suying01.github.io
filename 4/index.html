This project has two parts. In Part A I stitch photos into mosaics using correspondences I clicked by hand. In Part B the same mosaics are stitched automatically, by detecting, describing and matching features and estimating the homography robustly with RANSAC.

Part A: Image Warping and Mosaicing

In this project I took photographs and stitched them into image mosaics. The pipeline includes: clicking point correspondences between images, recovering the projective transformation (homography) between them with least squares, inverse-warping the images into a common frame with my own nearest-neighbor and bilinear interpolation, and blend the overlapping regions to reduce visible seams. The same warping code is also used to rectify photos of rectangular objects.

A.1: Shoot the Pictures

For each mosaic I stood in one spot and only rotated the phone, keeping the center of projection fixed so that the images are related by a pure projective transformation. Neighboring shots overlap by roughly 40–70%. I also used the main 1x lens and tried to keep the camera steady and at the same height.

A.2: Recover Homographies

A homography maps a point p = (x, y, 1) in one image to p' = Hp in the other, where H is a 3×3 matrix with 8 degrees of freedom (I fixed h33 = 1). Writing it out and dividing by the third coordinate: 

x' = (h11 x + h12 y + h13) / (h31 x + h32 y + 1)
y' = (h21 x + h22 y + h23) / (h31 x + h32 y + 1)

Multiplying through by the denominator makes each equation linear in the unknowns h = [h11 h12 h13 h21 h22 h23 h31 h32]T, so every correspondence contributes two rows to a system Ah = b: 

[ x  y  1  0  0  0  -x·x'  -y·x' ] h = x'
[ 0  0  0  x  y  1  -x·y'  -y·y' ] h = y'

Four correspondences give exactly 8 equations, but then a couple of pixels of clicking error can change H drastically. I instead click 8–9 correspondences per pair, spread across the overlap, and solve the overdetermined system with least squares (np.linalg.lstsq). Before solving, I apply Hartley normalization: each point set is translated so its centroid is at the origin and scaled so its mean distance from it is √2. This makes the columns of A similar in magnitude (raw pixel values and their products can differ by six orders of magnitude), which makes the least-squares solve numerically stable. The solution is then denormalized: H = T2-1 Hn T1.

A.3: Warp the Images

Inverse warping

warpImageNearestNeighbor(im, H) and warpImageBilinear(im, H) both use inverse warping. First, the four image corners are pushed through H to find the bounding box of the output. Then, for every pixel in that box, I apply H-1 to find where it came from in the source image and sample the source there. Because every output pixel is visited exactly once, there are no holes as compared to forward warping. Output pixels whose source location falls outside the input image are marked 0 in an alpha mask, which is later used for blending. I use the convention that (0,0) is the center of the top-left pixel. The whole computation is vectorized with NumPy and processed in row chunks to keep memory bounded.

  • Nearest neighbor: round the source coordinate to the closest pixel and copy its value.
  • Bilinear: take the four surrounding pixels and blend them with weights (1−dx)(1−dy), dx(1−dy), (1−dx)dy, dx·dy, where dx, dy are the fractional offsets.

Rectification

To test the warp, I rectified photos of known rectangular objects. I clicked the four corners (top-left, top-right, bottom-right, bottom-left) and mapped them to a hand-defined rectangle with the object's real aspect ratio, then warped the whole image with that homography.

Timings from results/rect*/timing.txt.

Quality: nearest neighbor copies one source pixel per output pixel, so wherever the image is magnified or rotated, edges become jagged and stair-stepped and texture looks blocky. This is most visible on the stretched far side of the object and on diagonal edges in the zoomed crops. Bilinear interpolation blends the four surrounding pixels, producing smooth edges and gradients. Its only visual cost is a slight softening of fine detail, since averaging acts as a small low-pass filter.

Speed: nearest neighbor needs one lookup per output pixel, while bilinear needs four lookups plus the weight computation. In these runs bilinear took about 1.9× as long for Example 1 and 2.9× for Example 2. Both are dominated by the shared cost of applying H-1 to every pixel, so the gap is smaller than 4×.

Trade-off: nearest neighbor is good enough for quick previews or when speed matters (e.g. video). For final results the small extra time for bilinear is worth it, so I use bilinear for all the mosaics.

A.4: Blend the Images into a Mosaic

Procedure

  1. Reference frame. I leave the middle image unwarped and warp the others into its projection. Using the middle image as the reference spreads the perspective distortion evenly to both sides.
  2. Homographies. For each side image I compute H mapping it to the reference from 8–15 clicked correspondences (A.2).
  3. Canvas size. I push every image's four corners through its H and take the bounding box of all of them, so the final mosaic size is known in advance (one-shot procedure).
  4. Warping. Every image is inverse-warped with bilinear interpolation into that shared canvas, giving a stack of aligned images, each with its own alpha mask.
  5. Feather weights. Each image gets a weight map from the distance transform (bwdist): 1 at the image center, falling off to 0 at its edges. The weight map is warped together with the image, as an extra channel, so it lives in the mosaic frame.
  6. Blending: 2-level Laplacian pyramid. Plain weighted averaging (feathering) removes hard seams but blurs or "ghosts" fine detail wherever two images are slightly misaligned. So I split each warped image into a low-frequency band (Gaussian blur, σ = 3, normalized by the alpha mask so the black border doesn't bleed in) and a high-frequency band (image minus low band).
    • The low bands are combined with the feathered weighted average, giving smooth color and exposure transitions.
    • The high bands are not averaged. At each pixel I take them from the image with the largest weight, which keeps edges and texture sharp and avoids ghosting.
    The final mosaic is the sum of the two blended bands.

For comparison, each mosaic is also shown with naive overwriting (later images simply cover earlier ones) and with plain feathering.

Observations

Naive overwriting produces visible seams wherever exposure differs slightly between shots. Feathering hides these seams by fading smoothly from one image to the next, but small misalignments from imperfect clicks (or slight camera translation) show up as ghosting and blur in the overlap. The 2-level blend keeps the smooth color transition of feathering while taking fine detail from a single image, so the overlap stays sharp. Moreover, I also learnt that keeping my chosen points well distributed throughout the image help images align much better.

Part B: Feature Matching for Autostitching

In Part B the mosaics are stitched automatically, with no clicked correspondences. In this section, I detect corners, describe each one with a small normalized patch, match the patches between images, and estimate a robust homography with RANSAC. That homography then goes through the same warping and blending code from Part A. I used the same three photo sets as Part A, so the automatic and manual results can be compared more clearly.

B.1: Harris Corners and Adaptive Non-Maximal Suppression

Harris corner detection

I used the provided harris.py code at a single scale (σ = 1, no sub-pixel refinement). It computes the Harris corner response f at every pixel of the grayscale image and returns all local maxima. Corners within 20 px of the border are discarded so that the 40×40 descriptor window in B.2 always fits inside the image. Detection is run on the same downscaled images as Part A (1200 px on the long side), so the automatic and manual homographies are in the same coordinates.

Harris returns thousands of corners per image. They are heavily clustered on texture and noise, and many of them are too weak or too close together to be useful.

Adaptive Non-Maximal Suppression (ANMS)

For a well-constrained homography the features should be spread over the whole image. ANMS solves this by giving each corner xi a suppression radius: the distance to the nearest corner that is clearly stronger than it. 

r_i = min_j || x_i - x_j ||    such that   f(x_i) < c_robust · f(x_j),    c_robust = 0.9

The globally strongest corner gets an infinite radius. A corner with a large radius is the strongest point in a large neighborhood, so I keep the 500 corners with the largest radii. The factor c_robust = 0.9 means a neighbor only suppresses a corner if it is at least about 10% stronger, so two corners of nearly equal strength don't suppress each other because of noise. The radii are computed for all pairs of candidates at once with NumPy, in chunks of rows to keep memory bounded.

Results: all Harris corners (left) vs after ANMS (right)

Without ANMS, corners pile up wherever there is fine texture which is essentially many points throught the whole picture. After ANMS the 500 remaining corners cover the whole image fairly evenly, including the less textured regions, while still sitting on distinctive structure. The corners that remain are much more distinctive, well-distributed, and look like something a human would select as corresponding points.

B.2: Feature Descriptor Extraction

For each ANMS corner I extract a descriptor, simplified to be axis-aligned (no rotation invariance) and without the wavelet transform:

  1. Large window. Take the 40×40 window centered on the corner.
  2. Blur. The grayscale image is first blurred with a Gaussian (σ = 2). This low-pass filter prevents aliasing when the window is subsampled.
  3. Subsample. Sample the blurred window every 5 px, giving an 8×8 patch. Each of the 64 values summarizes a 5×5 area, so the descriptor is smooth and tolerates the small (1–2 px) localization errors of single-scale Harris corners.
  4. Bias/gain normalization. Subtract the patch's mean and divide by its standard deviation, so the descriptor has zero mean and unit variance. This makes it invariant to brightness (bias) and contrast (gain) changes between photos, e.g. when the camera's exposure changes between shots.

Sampling the 8×8 patch from a larger, blurred 40×40 window matters: a raw 8×8 crop would contain mostly pixel noise and would change completely under a 1–2 px shift.

Results: sample features

The 8×8 descriptors keep the coarse structure of each window (the direction of an edge, where the bright and dark regions are) while discarding fine pixel detail. After normalization, every descriptor uses the full gray range regardless of how bright or dark the original window was.

B.3: Feature Matching

Each descriptor is flattened to a 64-dimensional vector. For every feature in the side image I compute the SSD to every feature in the reference image and find its nearest neighbor and second-nearest neighbor.

Subsequently, I use Lowe's ratio test which states that a correct match should be much better than the second-best candidate, while a wrong match is usually about as good as the second-best one. A match is accepted only if 

e_1NN / e_2NN  <  0.5        (e = SSD between descriptors)

I chose a threshold of 0.5 on the squared errors to keep most of the correct matches while rejecting the incorrect ones. This is because orrect matches are concentrated at low values, while incorrect matches cluster near 1.

Results: matched features

Each line connects a feature in the side image (left) to its match in the reference image (right). Each match has its own color.

Most matches run roughly parallel, which is what a consistent camera rotation produces. The few lines that cross the others at steep angles are incorrect matches that passed the ratio test. By observing the matches, the wrong matches often come from visually similar regions, for instance repeated patterns or similar-looking textures.

B.4: RANSAC and Automatic Mosaics

4-point RANSAC

The RANSAC algorithm is as follows:

  1. Randomly pick 4 matches and compute the exact homography through them with computeH from Part A.
  2. Map every matched point from the side image through this H and measure how far it lands from its partner in the reference image. Matches within 3 px are inliers.
  3. Repeat 5000 times and keep the largest inlier set. Degenerate samples (for example, nearly collinear points) are skipped.
  4. Refit H with least squares on all inliers, recompute the inliers with the refit H, and refit once more.

Observations

The automatic mosaics are built from many more correspondences than the 8–9 I clicked by hand, and every one of them is checked against the others by RANSAC. Clicking errors average out less well with few points, and a single bad click (like the 5.6 px point in Part A) pulls the whole least-squares fit. With automatic matching, inconsistent points are simply rejected. From mosaic 2, we can see that the automatic version is much sharper especially in the grass patch. It was hard finding corresponding points in the grass patch manually but automatic matching handled it well.
